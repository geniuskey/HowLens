# HowLens — 사진 먼저, 근거는 가까이

2026-10-09 / W3 design handoff / 사용자 팀장 레퍼런스 최우선 / 구현 전 콘셉트. 모드: Operate. 제품 사실은 [PRODUCT.md](PRODUCT.md), 모든 화면·복구는 [SCREENS.md](SCREENS.md). Android 소유자는 App Worker이며 이 문서는 제품 코드 변경이 아니다.

**선택: 사진이 화면의 중심이고, 바로 다음 행동 하나가 하단에 놓이는 Android 작업 도구.** 긴 설명 대신 촬영 대상과 다음 행동이 먼저 보인다. 상세를 접어도 위험·필수 미확인 조건·mock 여부는 숨기지 않는다. 입력과 결과를 별도 화면으로 나누고 뒤로 가면 작성 중 자료를 보존한다. 11:54 KST 최신 확정에 따라 입력 상단에 `사진 분석` / `카메라` 두 탭을 추가하며 두 탭 모두 단일 사진 API를 사용한다.

## 디자이너 관점·선택 근거

페르소나: 현장 서비스와 안전 관련 정보 계층을 전문으로 하는 시니어 Android 제품 디자이너. 판단 순서는 ①해야 할 행동을 3초 안에 찾는가 ②한 손으로 닿는가 ③짧은 한국어가 읽히는가 ④실패해도 입력이 남는가 ⑤근거와 불확실성이 구분되는가. 실제 사용자 인터뷰/장갑/조도/실물 테스트는 미실행이다.

| 검토 방향 | 작업 성공 / 위험 | 판정 |
|---|---|---|
| 사진 중심 작업 화면 | 카메라·선택 사진이 먼저 보이고 다음 행동 하나. 근거가 접히므로 펼침 행은 단계 바로 아래 항상 노출 | **선정**, 사용자 최신 선호와 현재 TakePicture 구현에 가장 맞음 |
| 점검표 중심 화면 | 누락 조건 파악은 좋으나 촬영 전에 많은 문장을 읽게 됨 | 사전 조건 상세 내부에만 사용 |
| 문서·근거 중심 화면 | 출처 비교는 쉽지만 작은 화면이 텍스트로 차고 촬영 동선이 약함 | 근거 상세 화면에만 사용 |

Impeccable context 1회 실행; root PRODUCT 부재 guard를 확인하고 허용 폴더에 제품 사실을 기록했다. 실제 concept-seed 성공은 1회, key `84abca0b`, assigned index 7. 후보군은 현장 사진 앨범, 점검표, 매뉴얼 여백, 계기 상태판, 정비 인수표, 작업 티켓, 카메라 검토 화면의 일곱 체계이며 실행 후 매핑한 것이므로 사전 무작위 실험으로 주장하지 않는다. 사용자 위임과 사진 중심 지시가 seed보다 우선하며 임의 재추첨/결정 UI/툴 업데이트를 하지 않았다.

Seed 대안은 고객 친숙도/제품 명료도 두 축으로 검토했다: 지도(낮음/낮음: 위치 근거 없음), 사전(낮음/낮음: 본문 과밀), 제품 증거 마케팅(보통/보통: 증거 결합은 유용하나 Operate 구조 아님), 항공권(낮음/보통: 한 구간 한 행동만 차용), Crouwel 격자(낮음/낮음: 가독성 저해), 출발 안내판(보통/낮음: 장비 다중 상태·시간표 없음). 모두 전체 방향으로는 declined. 보강 원칙: 지도에서 정보/안내 분리, 사전에서 명확한 상세 계층, 증거 마케팅에서 주장 옆 출처, 항공권에서 다음 행동 한 개, 격자에서 일관 간격, 안내판에서 상태 변경에도 위치 유지. 장식 모티프·서체·애니메이션은 차용하지 않는다.

## 시각 권위

사용자가 제공한 [팀장 레퍼런스 원본](../../../../assets/design/reference/team-lead-howlens-original.png)을 무변경 보존했다. 11:52 KST coordinator 전달 이후 이 자료가 초기 청록 제안보다 우선한다. HowLens scanner-square 로고와 블루 wordmark, 사진 중심 단계, 하단 결과 시트를 계승한다. 원본의 iOS chrome, PC 수리 범위, 추천 피드/채팅/프로필, 안전·완료 단정은 계승하지 않는다. 초기 청록 콘셉트는 폐기된 탐색안이며 최종 에셋에 포함하지 않는다.

## 토큰 — Compose Material 3 역할로 연결

Dynamic Color는 이번 단일 데모에서 사용하지 않는다. 아래 정적 light/dark 쌍으로 일관성을 유지하며, dark는 실제 APK 검증 전이다. RGB 대비는 상대휘도 공식으로 계산했으며 렌더/접근성 Scanner 통과를 뜻하지 않는다.

| 역할 | Light | Dark | 적용 |
|---|---|---|---|
| background / surface | #F3F4F6 / #FFFFFF | #101827 / #182337 | 화면 / 입력·시트 |
| onSurface | #111827 | #E5EAF2 | 본문, 제목 |
| onSurfaceVariant | #4B5563 | #B4C0D3 | 보조 문구·모드 |
| primary / onPrimary | #0052FF / #FFFFFF | #A9C3FF / #00286B | 유일 주행동·선택 표시 |
| secondary | #14B8A6 | #14B8A6 | 장식/진행 위치 강조만; 흰 바탕 작은 글자·성공/안전 표시 금지 |
| outline | #6B7280 | #93A4BE | 폼 경계·포커스; 작은 본문에 쓰지 않음 |
| warningContainer / onWarning | #FFF0C2 / #694F00 | #FFF0C2 / #694F00 | 미확인, 아이콘+짧은 상태 |
| errorContainer / onErrorContainer | #FFE8E5 / #9F2424 | #FFE8E5 / #9F2424 | 중단·입력 오류; dark도 같은 대비 쌍 |

계산 대비: 본문/배경 16.12:1, 보조/배경 6.87:1, 흰색/blue 5.75:1, warning 6.8:1, error 6.51:1. dark 본문 14.71:1, 보조 9.66:1, CTA 7.87:1. outline/white 4.83:1. teal/white 2.49:1이므로 청록을 흰 배경 작은 본문이나 유일 상태 식별색으로 쓰지 않는다. 색상만으로 상태를 전달하지 않는다. 경고/중단 아이콘과 짧은 한국어를 함께 쓰며 성공 체크로 안전을 암시하지 않는다.

- 서체: 레퍼런스는 Pretendard. 기존 번들에 없으면 다운로드 의존성 없이 `FontFamily.Default`(Android 한국어 시스템 fallback), 임의 영문 디스플레이 폰트/네트워크 폰트 없음. 제목 24sp/32sp Medium, 앱바 20sp/28sp Medium, 섹션 18sp/26sp Medium, 본문·입력·버튼 16sp/24sp Regular/Medium, 모드·판본 14sp/20sp. 필수 경고는 16sp. 자간 기본, 한글 강제 대문자·단어별 분절 없음.
- 여백: 4/8/12/16/20/24/32dp. 화면 좌우 20dp(320dp 화면은 16dp), 항목 사이 12dp, 섹션 사이 24dp. 관련 없는 정보를 카드로 쪼개지 않는다.
- 터치: 모든 버튼·아이콘·펼침 행 ≥48×48dp, 인접 터치 영역 사이 ≥8dp. 주행동 minHeight 56dp, 높이는 내용에 따라 증가. 카메라 원형 셔터를 흉내 내지 않고 인식 가능한 카메라 아이콘+`사진 찍기` 사용.
- 모양: 버튼 16dp, 사진/입력 12dp, bottom sheet 상단 24dp. 1dp 경계. 그림자 없음, 시트만 기본 Material elevation. 아이콘 Material Symbols outlined 24dp, 장식 아이콘 TalkBack 제외.
- 사진: 전체 프레임 `ContentScale.Fit`, 4:3 컨테이너가 기준. 회전·잘림 없이 원본 구도를 확인. 일반 폰에서 최대 화면 높이 36%, 작거나 큰 글꼴이면 28%로 줄이고 텍스트를 우선. 사진 대신 임의 서버 이미지를 런타임에 넣지 않는다.
- 앱바: 56dp 최소, 상태바 별도 inset. `HowLens` 또는 현재 작업명, 설정/공유는 48dp 영역. 최신 사용자 요청의 상단 탭 2개만: `사진 분석` / `카메라`, 각각 minHeight 48dp, selected underline + semantics. 존재하지 않는 히스토리/대시보드/채팅/프로필 탭 금지.
- CTA: 하단 Surface, 좌우 20dp/위아래 12dp + navigationBars inset. 스크롤 영역에 하단 실제 높이만큼 여유. 키보드 위로 올라가며 `imePadding` 중복 소비 금지. 짧은 높이/200% 글꼴에서 viewport를 잠식하면 CTA도 스크롤 문맥으로 전환하고 필드 BringIntoView 유지.
- 전환: 150–200ms fade, 과한 스캔/레이저/가짜 진행률 없음. 시스템 애니메이션 제거 존중. 실제 서버 단계가 없으면 `사진을 확인하고 있어요`와 indeterminate progress만 사용.

## 정보 노출 규칙

기본 첫 화면은 앱명, 작은 `데모` 또는 `실제 분석`, 선택 장비, 사진 영역, 질문, 주행동만. 안내 문단·파일 수치·서버 주소·예시 시나리오 칩은 설정/오류/상세로 이동한다. 데모 결과에서는 짧은 `실제 작업에 사용하지 마세요`를 한 번 표시한다. `실제 분석`은 모드 표시이며 안전 승인이라는 문구를 쓰지 않는다.

기본 결과는 사진 + 판정 한 줄 + 필요한 이유 한 줄 + 다음 행동. 상세한 observations, 원문 경고, missing_information, 모든 preconditions/evidence를 삭제하거나 요약으로 대체하지 않고 펼쳐서 읽게 한다. 중대한 경고와 미충족 필수 조건은 접지 않는다. 좁다고 중요한 안전 문장을 ellipsis 처리하지 않는다. 9개 이미지는 9개 단계가 아니며 각 panel의 step_id를 유지한다.
