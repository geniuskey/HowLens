# HowLens — AI 기반 PC 문제 해결 모바일 웹앱 개발 프롬프트

## 1. 프로젝트 목표

첨부된 HowLens UI 컨셉 이미지를 참고하여, **HowLens라는 AI 기반 PC 문제 해결 서비스를 실제로 사용할 수 있는 반응형 웹 애플리케이션**으로 구현하라.

HowLens는 사용자가 PC의 문제 상황을 카메라로 촬영하면 AI가 이미지와 상황을 분석하고, 초보자도 쉽게 이해할 수 있는 단계별 해결 가이드를 제공하는 서비스다.

핵심 슬로건:

* HowLens: 보면, 할 수 있어요.
* PC 문제 해결, 이제 관찰하고 따라만 하세요.
* AI가 보는 순간, 복잡한 PC 작업도 쉬워집니다.

단순한 랜딩 페이지나 정적인 UI 목업을 만들지 않는다. 실제 화면 전환, 이미지 업로드, 카메라 실행, 분석 진행 상태, 단계별 가이드, AI 채팅 및 완료 확인까지 동작하는 프로토타입을 구현한다.

## 2. 핵심 사용자 경험

다음의 사용자 여정을 중심으로 전체 서비스를 설계한다.

1. **문제 발견:** 사용자가 PC 조립, 부품 교체, 업그레이드 또는 고장 상황에 직면한다.
2. **사진 촬영:** 사용자가 카메라를 실행하거나 기존 사진을 업로드한다.
3. **AI 분석:** 이미지에서 부품을 식별하고 문제 상황과 예상 원인을 분석한다.
4. **단계별 가이드:** 초보자가 따라 할 수 있도록 사진, 설명, 확인 포인트를 단계별로 제공한다.
5. **직접 확인:** 사용자가 각 단계를 수행하고 확인 버튼을 누른다.
6. **완료 확인:** 작업 결과를 확인하고, 문제가 남아 있으면 추가 가이드나 AI 채팅을 제공한다.

모든 화면과 인터랙션은 이 사용자 여정에 집중해야 한다.

## 3. 기술 구현 원칙

프로젝트에 이미 설정된 프레임워크, 패키지 관리자, 디렉터리 구조 및 코딩 규칙을 먼저 확인한다. 기존 프로젝트가 있다면 이를 존중하고 불필요하게 재구성하지 않는다.

신규 프로젝트라면 다음을 기본 방향으로 사용한다.

* React + TypeScript
* Vite
* Tailwind CSS
* Lucide 아이콘
* 재사용 가능한 UI 컴포넌트
* 모바일 우선 반응형 레이아웃
* 실제 모바일 카메라를 지원하는 웹 표준 API
* 브라우저에서 동작하는 상태 관리 및 폼 처리

별도의 백엔드나 AI API가 제공되지 않았다면 프런트엔드 프로토타입만으로 동작하도록 구현한다. 이 경우 현실적인 모의 데이터를 사용하되, 나중에 실제 AI API와 연동할 수 있도록 서비스 계층을 분리한다.

불필요한 대형 라이브러리나 복잡한 상태 관리 프레임워크는 추가하지 않는다.

## 5. 필수 화면

### A. 홈 화면

첨부 이미지의 메인 스마트폰 화면을 기준으로 구현한다.

구성 요소:

* 상단 HowLens 로고
* 검색, 알림, 프로필 아이콘
* 핵심 문구: "PC 문제, 보면 바로 알 수 있어요."
* 사진 촬영 및 문제 해결을 안내하는 메인 배너
* 주요 액션 버튼: "지금 촬영하기"
* 주요 카테고리:

  * 조립하기
  * 부품 교체
  * 문제 해결
  * 업그레이드
* 추천 가이드 카드

  * 그래픽카드 장착하기
  * SSD 교체하기
  * 메모리 업그레이드
  * 케이블 연결 확인하기
* 하단 탭 바:

  * 홈
  * 가이드
  * 촬영하기
  * AI 채팅
  * 내 정보

메인 CTA는 실제 촬영 화면으로 이동해야 한다.

### B. 카메라 촬영 화면

HowLens의 핵심 화면이다.

구성 요소:

* 카메라 프리뷰
* 화면 중앙의 블루 포커스 프레임
* 촬영 대상 안내
* 카메라 전환 및 플래시 컨트롤(지원 환경에서만 활성화)
* 사진 촬영 버튼
* 사진 및 동영상 모드 표시
* 배율 선택 UI
* 촬영 취소 및 결과 확인 액션

동작 요구사항:

* 모바일 브라우저에서는 `getUserMedia()`를 이용해 카메라를 실행한다.
* 카메라 접근 권한이 거부되거나 지원되지 않으면 파일 업로드 대안을 제공한다.
* `input[type=file]`의 이미지 선택과 모바일 카메라 촬영도 지원한다.
* 촬영한 이미지를 미리 볼 수 있어야 한다.
* 촬영 결과를 다시 찍거나 분석할 수 있어야 한다.
* 카메라 권한 오류를 친절하게 안내한다.
* HTTPS 및 브라우저 권한 정책을 고려한다.

카메라 프레임은 장식에 그치지 않고 사용자가 PC 부품을 화면 안에 배치하도록 안내하는 역할을 한다.

### C. AI 분석 화면

사진 촬영 후 AI가 분석하는 화면이다.

구성 요소:

* 촬영한 이미지 미리보기
* 분석 중 상태 표시
* 분석 진행 상황을 알려주는 메시지
* 부품 인식 결과
* 감지된 문제 후보
* 다음 단계 안내

예시 메시지:

* "PC 내부 부품을 확인하고 있어요."
* "그래픽카드와 PCIe 슬롯을 분석하고 있어요."
* "전원 케이블 연결 상태를 확인하고 있어요."
* "분석 결과를 바탕으로 해결 방법을 준비하고 있어요."

AI 분석 API가 없다면 타이머에 의존해 성공을 확정하지 않는다. 명시적인 모의 분석 상태를 사용하고, 분석 완료 후 사용자가 결과 화면으로 이동할 수 있도록 한다.

### D. 단계별 가이드 화면

첨부 이미지의 가이드 화면을 충실히 반영한다.

구성 요소:

* 상단 뒤로 가기
* 가이드 제목
* 현재 단계 및 전체 단계 수
* 진행률 표시
* 단계 제목과 상세 설명
* 해당 작업을 보여주는 이미지
* 이미지 내 확인 포인트
* 주의사항 및 안전 안내
* 이전 단계 및 다음 단계 버튼
* AI에게 질문하기 버튼

예시 시나리오: 그래픽카드 장착 상태 확인하기

1. PC 전원을 종료하고 전원 케이블을 분리한다.
2. 그래픽카드가 PCIe 슬롯에 올바르게 장착되었는지 확인한다.
3. 그래픽카드 보조 전원 케이블 연결 상태를 확인한다.
4. 그래픽카드 고정 상태와 주변 케이블 간섭을 확인한다.
5. 케이스를 닫기 전에 점검 결과를 확인한다.

각 단계는 독립적인 데이터 객체로 관리한다.

사용자가 다음 단계로 이동하면 진행 상태가 갱신되어야 한다. 이전 단계로 돌아가도 완료 상태가 유지되어야 한다.

하드웨어 작업의 위험성을 고려해 전원 차단 및 제조사 지침 확인 등 적절한 안전 안내를 제공한다. 전원이 연결된 상태에서 내부 부품을 만지도록 안내하지 않는다.

### E. 완료 확인 화면

구성 요소:

* 작업 결과 이미지
* 완료 상태 아이콘
* "작업이 완료되었어요!" 메시지
* 수행한 작업 요약
* 최종 확인 체크리스트
* 다른 문제 해결하기 버튼
* 완료 버튼

사용자가 체크리스트를 확인하고 완료를 명시적으로 선택할 수 있도록 한다.

작업이 성공했다고 AI가 무조건 단정하지 않는다. 사용자가 직접 완료 여부를 확인하도록 설계한다.

### F. AI 채팅 화면

구성 요소:

* HowLens AI 헤더
* 이전 분석 내용과 연계된 대화
* 사용자 메시지 및 AI 메시지
* 관련 부품 이미지 미리보기
* 추천 질문
* 메시지 입력창
* 전송 버튼

예시 대화:

사용자: "그래픽카드를 장착했는데 화면이 나오지 않아요."

HowLens AI: "전원 연결과 그래픽카드 장착 상태를 순서대로 확인해 볼게요. 먼저 그래픽카드의 보조 전원 케이블이 제대로 연결되어 있는지 확인해 주세요."

추천 질문:

* 전원 연결 확인하기
* 그래픽카드 다시 장착하기
* BIOS 설정 확인하기

메시지 전송, 대화 내역 표시, 추천 질문 선택은 실제로 동작해야 한다. 실제 AI 연결이 없다면 규칙 기반 모의 응답을 사용하고, 추후 API 연동이 가능한 구조로 분리한다.

### G. 문제 분석 Bottom Sheet

촬영 결과나 분석 결과를 바탕으로 요약을 표시한다.

구성 요소:

* 촬영 이미지 썸네일
* 분석된 문제 설명
* 예상 원인 목록
* 원인별 체크 항목
* 단계별 가이드 보기 버튼
* 닫기 버튼

예시:

"그래픽카드가 슬롯에 완전히 장착되지 않았을 가능성이 있어요."

예상 원인:

* PCIe 슬롯에 완전히 삽입되지 않음
* 보조 전원 케이블 미연결
* 그래픽카드 고정 상태 불량

이는 진단 확정이 아니라 확인해야 할 가능성으로 표현한다.

* 즐겨찾기

## 8. 인터랙션 및 상태 관리

다음 상태 전이를 명확하게 구현한다.

홈 → 촬영 → 이미지 확인 → AI 분석 → 문제 요약 → 단계별 가이드 → 완료 확인

분석 중에는 로딩 상태를 표시하고, 오류가 발생하면 재시도 또는 이미지 변경이 가능해야 한다.

사용자가 화면을 이동하거나 이전 단계로 돌아갈 때 작업 상태가 불필요하게 초기화되지 않아야 한다.

브라우저 뒤로 가기와 직접 URL 접근도 가능한 범위에서 지원한다.

모든 버튼은 의미 있는 동작을 가져야 한다. 단순히 클릭 가능한 것처럼 보이지만 아무 동작도 하지 않는 UI를 만들지 않는다.

## 9. 반응형 레이아웃

주요 타깃은 모바일 사용자다.

* 모바일: 실제 스마트폰 앱에 가까운 전체 화면 경험
* 태블릿: 콘텐츠 폭과 카드 레이아웃 최적화
* 데스크톱: 중앙의 모바일 앱 형태 또는 좌우 패널을 활용한 넓은 작업 공간

모바일에서 하단 탭 바는 안전 영역을 고려해 배치한다. 화면이 작은 경우 콘텐츠가 잘리거나 버튼이 가려지지 않도록 한다.

데스크톱에서는 첨부 이미지와 같은 밝고 정돈된 디자인 시스템을 유지하되, 모바일 화면을 무조건 확대해서 배치하지 않는다.

## 10. 접근성 및 품질

* 모든 입력 요소에 적절한 레이블 제공
* 아이콘 전용 버튼에 접근 가능한 이름 제공
* 키보드 탐색 지원
* 색상만으로 상태를 구분하지 않음
* 로딩, 오류, 완료 상태를 명확하게 표시
* 이미지에 적절한 대체 텍스트 제공
* 긴 한국어 문장과 작은 화면에서의 줄바꿈 검증
* 카메라 권한 실패 및 이미지 업로드 실패 처리
* 콘솔 오류와 불필요한 경고 제거

## 11. 개발 진행 방식

먼저 프로젝트를 분석하고 다음 순서로 진행한다.

1. 기존 코드와 실행 환경을 확인한다.
2. 구현 계획 및 화면 구조를 정리한다.
3. 디자인 토큰과 공통 컴포넌트를 만든다.
4. 홈 화면과 하단 내비게이션을 구현한다.
5. 카메라 및 이미지 업로드 기능을 구현한다.
6. 분석 결과, 단계별 가이드, 완료 확인을 구현한다.
7. AI 채팅과 보조 화면을 구현한다.
8. 반응형 레이아웃과 접근성을 점검한다.
9. 개발 서버 실행 및 빌드를 검증한다.
10. 주요 사용자 여정을 직접 테스트하고 발견된 문제를 수정한다.

작업을 시작하기 전에 구현 계획을 간략하게 제시하되, 계획 설명만 하고 멈추지 않는다. 프로젝트 분석 후 실제 코드 작성과 검증까지 진행한다.
